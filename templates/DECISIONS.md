# DECISIONS

큰 판단 또는 검증 결과가 바뀔 때만 갱신한다. 실행 전에는 통과라고 쓰지 않는다.

## 환경·제출 운영 상태

| 항목 | 실제 값/출처 | 상태·실행 주체 |
|---|---|---|
| 준비/모의/실제 응시, 허용 자료 경로·도구 | | 미확인 |
| 작업 시작/제한・전체 종료・시간대, 질문 준비/서술형 여유 | | 미확인 |
| 서버 바인딩/실제 포트/Browser 경로 | | NOT_RUN |
| 에디터 저장됨/동시 수정 충돌 해결・필수 파일/실제 제출 범위 | | NOT_RUN |
| 제출 미리보기/제출물 확정 | | NOT_RUN (응시자) |
| 서술형・최종 처리/업로드・완료 화면 | | NOT_RUN (응시자) |
| 완료 화면의 제출 ID/시각/파일 수/크기 | | 미확인 |

단계별로 실제 확인한 것만 기록한다. 개인 PC git push/commit이나 제출물 확정만으로 실제 응시 완료라고 쓰지 않는다.
장애는 발생 시각·단계·직전 동작·오류/문항 번호·복구·신고를 기존 기록에 남긴다. 키/토큰은 적지 않고 타이머 자동 정지/보상을 가정하지 않는다.

## 실행 증거

| 실행 주체(AI/사용자/Reviewer)·명령·작업 디렉터리 | 대상/실행/skip 수·기대/실제・종료 코드 | 관련 파일/로그 | 범위·한계 |
|---|---|---|---|
| | 미실행 | | |

상태는 PASS / FAIL / INCOMPLETE / SKIP / NOT_RUN으로 구분한다.
테스트 0개·전부 skip·유효 출력 없는 결과를 통과로 적지 않는다. 필수 검증의 INCOMPLETE/SKIP은 완료를 차단한다.
선택 도구가 없으면 해당 검사만 SKIP 사유를 기록한다. 나머지 검증 통과가 그 검사를 수행했다는 뜻은 아니다.

## 원본 대조와 사용자 직접 확인

| 핵심 값/사용자 행동 | 원본·별도 계산식/조작 절차 | 기대 결과 | 실제 결과·실행 주체 | 상태 |
|---|---|---|---|---|
| | | | 미실행 | NOT_RUN |

AI가 실행한 명령을 사용자가 직접 실행했다고 쓰지 않는다. 실제 브라우저 조작과 HTTP 테스트도 구분한다.
UI 과제라면 검색→상세→수정→새로고침 같은 대표 행동 하나를 직접 확인할 절차를 남긴다.

## AI 없이 6문항 (각 5분)

연습 분류이며 실제 시험 문항·순서를 예측하지 않는다. 실제 파일·함수 이름으로 질문을 구체화한다.

1. 핵심 함수의 설계 선택·대안·포기한 것은? 필수 규칙과 개선 목표가 충돌하면 무엇이 우선인가?
2. 원본에서 화면까지 어떤 모듈을 거치며 상태는 어디에 저장되는가? 재시작하면 무엇이 유지되는가?
3. 구현/가정/미구현은 각각 무엇이며 어떤 파일·명령·결과로 재현하는가?
4. 잘못된 입력·저장 실패·중복 요청 때 기존 결과/화면은 어떻게 되는가? 확인한 것과 미확인을 나누어라.
5. 가장 깨지기 쉬운 곳과 데이터 변경 시 확인할 조건은? AI 설명과 다른 경로의 근거는 무엇인가?
6. 현업 답변·사용자 판단·AI 제안은 어떻게 구분되는가? 실제 수용/수정/거절 한 건과 검증 근거는?
