## 요구사항/구현 리뷰와 기존 담당 에이전트 수정

| 단계·요구/지적 ID | Reviewer·별도/동일 세션 | 출처/파일·반례/재현 | 기대/실제·영향 | 심각도/확인 필요 | 기존 작성/개발 에이전트 ID·수정/자체검증 | Reviewer 재검증·상태 |
|---|---|---|---|---|---|---|
| | | | | | | |

Reviewer는 보고만 반환한다. 조정 에이전트는 지적을 기존 담당자(ID/세션)에게 전달한다. 기록/계약/코드/테스트 반영과 수정·자체검증은 해당 결과물을 작성·개발한 기존 담당 에이전트가 수행하고 Reviewer가 재검증한다.
검토한 요구와 아직 검토하지 않은 요구를 구분한다. 근거 없는 비판은 확정 결함으로 적지 않는다.

## 요구별 구현·실행 증거

| 요구/AC | 구현 파일 | 명령·실행 위치·실행 주체 | 기대/실제·종료 코드·실행/skip 수 | 리뷰/재검증 | 상태·미검증 |
|---|---|---|---|---|---|
| | | | | | NOT_RUN |

PASS/FAIL/INCOMPLETE/SKIP/NOT_RUN을 구분한다. 필수 검증의 미실행/검사0/전부skip은 완료를 차단한다.
AI 실행·사용자 직접 확인·독립 Reviewer, 자동 HTTP·실제 Browser를 구분한다. 원본/별도 계산 대조와 변환 수지도 관련 AC에 기록한다.
합성 결함은 사전 정답·분모/발견·미검출을 기록하고 실제 발견 결함과 구분한다. 실행하지 않은 결과·사용자 결정을 만들지 않는다.
