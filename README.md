# COFA Development Playbook

180분 내 요구사항 구현, 데이터 검증, 판단 근거 설명을 연습하는 개인용 플레이북.
SK하이닉스 또는 시험 주관사의 공식 자료가 아니다. 시험 조건은 사용자가 제공한 상세 가이드를 대조해 보강했으며 실제 최신 공지·과제 안내가 우선한다.
모든 모의 데이터와 업무 규칙은 합성이다. 실제 문제·회사 데이터·개인정보·원본 PDF는 포함하지 않는다.

## 시작

1. 실제 과제 README와 데이터만 읽고 [PROMPTS.md](PROMPTS.md)의 Analyze & Interview를 실행한다.
2. 준비 연습에서는 [CONTRACT 템플릿](templates/CONTRACT.md), [DECISIONS 템플릿](templates/DECISIONS.md)을 사용한다. 실제 응시에서는 허용된 자료 경로·과제 지정 파일명을 따른다.
3. 분석·인터뷰 → 요구사항 리뷰 → 개발 → 구현 리뷰 → 이해·제출 순서로 진행한다. 먼저 구현할 요구부터 검토하고, 수정은 해당 결과물을 작성·개발했던 에이전트가 수행한다.
4. AI 없이 6문항에 각각5분 답하는 연습을 한다. 실제 문항 수는 응시 화면을 확인하며, 서술형·질문 준비 대기도 전체 종료 시각 안에 마쳐야 한다.

응시 환경 준비와 제출 때는 아래 [체크리스트](#응시와-제출-체크리스트)를 확인한다.

먼저 사용자·사용 순간·업무 결과와 성공 지표를 확인하고, 필수 규칙/개선 목표/범위 밖을 구분한다.
테스트 종료 코드만으로 완료라 하지 않는다. 실제 실행/skip 수, 대표 원본 대조, 사용자의 직접 확인 여부를 기록한다.
공개 준비 저장소 6곳의 비교와 적용 근거는 [BENCHMARK.md](BENCHMARK.md)에 있다. 외부 코드·문구를 복제하지 않고 필요한 원칙만 자체 구현했다.

우선순위: **필수 기능 > 데이터 정확성 > 실행 검증 > 판단 근거 > 도구 편의성**.
새 Skill·MCP·설치 스크립트·병렬 에이전트는 기본 구성에 필요하지 않다.
환경이 지원·허용하면 별도 Reviewer 1개에 [요구사항/구현 리뷰 프롬프트](PROMPTS.md)를 전달할 수 있다. Reviewer는 보고만 반환하고 원래 개발 담당 에이전트가 수정·자체검증한 뒤 Reviewer가 재검증한다.

## 180분 운영 예시

| 구간 | 작업 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 0–30분 | README/데이터 분석, 핵심 현업 질문, 요구사항 리뷰 | 먼저 구현할 요구의 근거/완료 조건 검토, 불확실성 식별 |
| 30–120분 | 가장 작은 전체 흐름 → 필수 기능 | 실행 가능, 요구사항별 자체 테스트 |
| 120–155분 | Reviewer 반례·원래 개발 담당 에이전트 수정·Reviewer 재검증 | P0/P1 해소 또는 미해결 근거 공개 |
| 155–170분 | 실행/제출 점검, 개발자 본인 설명 확인 | 파일·명령·결과·한계 일치, 이해 미확인 구분 |
| 170–180분 | 저장 확인·제출 미리보기·확정 | 미저장/충돌 해결. 확정 뒤 파일 수정 불가 |

시간표는 권장 상한이다. 분석 완벽주의로 구현을 지연하지 않는다. 답이 없으면 영향 없는 기능부터 구현하고, 업무 정책은 미확정으로 유지한다.
안내서의 전체 종료14:00은 서술형/질문 준비에도 적용된다. 늦게 시작했거나 대기가 길면 위180분 예시보다 일찍 작업을 끝내야 한다. 대기는 약5분 고정으로 보장되지 않는다.
P0: 실행 불가/원본 훼손/광범위 데이터 손상. P1: 필수 기능 오답·데이터 누락·계약 위반. P2: 핵심 기능을 막지 않는 사용성 문제.

## 모의 과제 실행

Python 3.10 이상과 브라우저만 필요하다. 패키지 설치 없음.

```powershell
cd practice/route-service
python app.py --port 8765
# 브라우저에서 http://127.0.0.1:8765
```

다른 터미널에서:

```powershell
cd practice/route-service
python profile_data.py
python rehearsal/verify.py --stage final
python evaluator/score.py
```

검증기는 필수 테스트가 0개이거나 전부 skip이면 종료 코드 2(INCOMPLETE)로 막는다.
선택 검사인 Node 문법 검사만 도구 부재 시 SKIP을 명시한다. 현재 테스트는 서비스/반례15개와 검증기 회귀6개다.
로컬 실행의 기본 바인딩은127.0.0.1이다. 제공 가이드의 플랫폼 Browser용 실행 옵션은 다음과 같다.

```text
python app.py --host 0.0.0.0 --port 8765
Browser: PORT=8765, 경로=/
```

실행 전에 Python 버전·기존 스택·실제 포트를 확인하고 서버 터미널을 유지한다. 두 모드의 로컬 HTTP/CLI 검증과 실제 플랫폼 미리보기는 구분한다.

독립 연습을 하려면 처음에는 **practice/route-service/README.md와 data/만** 읽는다.
`evaluator/`, 이미 작성된 `CONTRACT.md`, `DECISIONS.md`, `rehearsal/`, 구현 및 테스트는 첫 분석 전에 열지 않는다.
평가자는 `evaluator/RULES.md`로 질문에 답하고, 분석자가 제출한 질문/탐지 목록을 정답과 대조한다.
폴더 분리는 접근 통제가 아니다. 블라인드 연습은 별도 사본에서 evaluator/와 해설·구현을 제거해 진행한다.
현재 포함된 완성 예시는 해설용이며 시간제한 실험의 성적이 아니다.

```text
README.md / AGENTS.md / PROMPTS.md / BENCHMARK.md
templates/CONTRACT.md / DECISIONS.md

  profile_data.py            # 스키마/관계/손실 검사
  web/index.html / app.js / style.css
  tests/test_service.py      # Developer 실행 검증
  reviewer/test_adversarial.py # 별도 기준의 반례
  CONTRACT.md / DECISIONS.md   # 리허설 결과 계약·판단
  rehearsal/                # ANALYSIS/INTERVIEW/REVIEW/REPORT.md,
```

실제 실행 결과·검출률·현재 한계는 [DECISIONS](practice/route-service/DECISIONS.md)과 [리허설 보고](practice/route-service/rehearsal/REPORT.md)에 기록한다.
`.gitattributes`는 체크아웃 환경에 따라 CSV 줄바꿈과 기준 해시가 달라지는 것을 방지한다.

## 응시와 제출 체크리스트

근거: 사용자 제공 `3_사전_체험_및_응시환경_상세_가이드.pdf` 본문3·5~10장(PDF p.2~5), 검토2026-11-04. 최신 공지·개인 응시 화면·실제 과제 지침이 우선한다. 장치 설치·신분증 확인 등의 상세 절차는 원문을 따른다.
원본 SHA-256: `9b9c31e9c9395929cd7e5b818be48e68c877f73b66d73cdb0f3d9f560983cc6e`. 원본 PDF는 저장소에 포함하지 않는다.

- **사전 체험:** 안내된 1회15분 안에 제공 도구의 응답, 파일 작성/저장, Browser 동작과 감독 연결을 확인한다. 본 과제 시작과 구분한다.
- **도구·반입:** 제공 Codex와 허용 모델/자료 경로를 사용한다. 공개 자료 clone 허용을 현재 Private 저장소 반입 허용으로 해석하지 않는다. 실제 응시에서는 개인 파일 업로드·외부 전송·git push·개인 API 키/외부 AI 사용을 금지한 안내를 따른다. 공개 전환이나 제한 우회는 수행하지 않는다.
- **실행·저장:** 플랫폼 Browser의 실제 포트/경로·0.0.0.0 바인딩을 확인하고 서버 터미널을 유지한다. 연결 실패는 서버 오류→포트→바인딩→경로 순서로 확인한다. 에디터의 저장됨을 확인하고 AI/터미널과의 충돌은 양쪽 내용을 비교해 해결한다.
- **구현·데이터:** README 필수 기능/완료 기준과 실제 결과를 대조한다. 업무 답변과 미확정을 구분하고 원본 불변·변환 전후 행 수/손실을 확인한다.
- **검증·설명:** 실제 명령·결과·실행/skip 수를 기록한다. AI 실행/사용자 직접 확인/독립 Reviewer 여부를 구분하고, 선택한 이유·데이터 흐름·검증·남은 한계를 직접 설명한다.
- **시간:** 작업 제한과 전체 종료 시각을 함께 확인한다. 질문 준비·서술형까지 전체 종료 안에 마친다. 대기는 약5분으로 고정되지 않으며 AI 대기·재접속·비활성·신고/복구 중에도 타이머는 진행된다.
- **제출물 확정:** 종료10분 전 제출 점검을 시작한다. 필수 파일명/경로·AGENTS.md 요구 여부·저장 상태·실제 제출 범위를 확인한다. 미리보기에서 숨김 파일이 생략될 수 있고, 확정 후에는 수정할 수 없다. 수정이 필요하면 확정 전에 미리보기를 닫는다.
- **서술형·최종 완료:** 실제 문항 수를 확인하고 AI/복사·붙여넣기 없이 답한다. 다음 문항은 직전 제출 즉시 시간이 시작되고 이전 답안으로 돌아갈 수 없다. 마지막 답안 뒤 처리/업로드와 완료 화면의 제출 ID·시각·파일 수·크기를 확인한 뒤 종료한다. 제출물 확정과 최종 완료를 구분한다.
- **문의·장애:** 요구/제출물은 과제 README, 업무는 실무자 에이전트, 사용법/제출 절차는 Cofa Helper에 확인한다. 반복 오류/감독 장애는 문제 신고에 시각·단계·직전 동작·오류(서술형이면 문항 번호)를 적고 키/토큰은 제외한다. 시간 정지나 보상을 가정하지 않고 안내에 따라 복구한다.
