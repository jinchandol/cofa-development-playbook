# COFA Kit

과제 README에 따라 분석·개발·검증·제출 준비를 진행하는 개인용 COFA Kit.
요구사항·산출물·실행·제출 방식의 기준은 과제 원본 README와 최신 공식 안내다. Kit의 규칙·파일명·양식은 미지정 부분의 기본값이며, 충돌하면 해당 Kit 항목을 적용하지 않는다.
실제 과제 자료는 별도 과제 폴더에 유지하며 이 저장소에 포함하지 않는다.

## 과제 원본을 보존하며 가져오기

먼저 과제 README에서 자료 반입·파일 작성·도구 사용 조건을 확인한다. 허용된 범위에서 과제 루트 AGENTS.md를 새로 작성하고 Kit을 연결한다. 아래 명령은 과제 README.md가 있는 폴더에서 실행한다. Windows는 Git Bash, Linux는 sh를 사용한다.

```sh
git clone https://github.com/jinchandol/cofa-development-playbook.git ../cofa-kit && sh ../cofa-kit/install.sh
```

별도 기록 문서 지정과 추가 파일 제한이 없을 때의 기본 배치:

```text
작업공간/
  과제/                  # 작업 위치 유지
    README.md            # 과제 원본 유지
    AGENTS.md            # 설치 시 생성, 분석 후 과제별 지침 추가
    CONTRACT.md          # 시작 후 Codex가 작성: 요구사항·완료 조건
    DECISIONS.md         # 시작 후 Codex가 작성: 판단·검증·다음 행동
    STUDY.md             # 튜터 요청 시 생성: 개발자인 내 학습 노트
    data/                # 과제 원본 유지
  cofa-kit/              # 별도 Git 저장소, 설치 후에도 유지
    README.md            # 준비 안내
    AGENTS.md / PROMPTS.md / templates/ / install.sh
```

설치기는 과제 루트에 AGENTS.md를 초기 생성해 Kit 지침을 연결한다. 시작 요청을 수행하는 Codex는 먼저 과제의 문서명·양식·추가 파일 제한을 따르며 필요한 기록을 지정 문서에 맞춰 담는다. 별도 지정·제한이 없을 때만 templates/CONTRACT.md·templates/DECISIONS.md를 각각 복사해 과제 루트의 CONTRACT.md·DECISIONS.md를 작성한다. 기존 파일은 읽고 갱신하고 Kit 원본은 보존한다. 과제 AGENTS.md에는 확정된 실행·검증 명령과 주의점만 간결히 보완한다.
이미 직접 작성한 AGENTS.md가 있으면 원문을 보존하고 참조 블록만 추가한다. 같은 경로로 재실행해도 중복 추가하지 않는다. 과제 README.md·데이터·.git·.codex 설정은 변경하지 않는다. 기존의 불완전한 참조 블록이나 다른 경로가 발견되면 덮어쓰지 않고 중단한다.
COFA Kit 파일 전체를 과제 루트로 복사하거나 기존 저장소에 pull/merge하지 않는다. 목적지 ../cofa-kit이 이미 사용 중이면 clone을 중단하고 기존 폴더를 확인한다.

위 URL은 현재 Private 저장소의 개인 PC 연습용이다. 실제 응시에서는 공식적으로 허용된 저장소와 경로를 사용하며, Private 자료 반입이 허용된 것으로 추정하지 않는다.

## 시작

1. 과제 폴더에서 Codex에 아래 요청을 입력한다. [PROMPTS.md](PROMPTS.md#시작)는 과제 README 확인부터 시작한다.
2. 과제 지정 문서를 사용하고, 미지정 범위에서만 Kit 템플릿을 기본 기록 양식으로 사용한다.
3. 분석·인터뷰 → 요구사항 리뷰 → 개발 → 구현 리뷰 → 이해·제출 순서로 진행한다. 먼저 구현할 요구부터 검토하고, 수정은 해당 결과물을 작성·개발했던 에이전트가 수행한다.
4. 기능별 학습은 아래 흐름으로 진행하고 제출 전 본인 설명을 확인한다. 실제 서술형의 문항·시간·AI 사용 규칙은 공식 안내를 따른다.

```text
과제 원본 README를 먼저 확인하고, 허용된 범위에서 COFA Kit PROMPTS.md의 '시작' 요청대로 진행해줘.
```

허용된 작업에 적용할 분석·리뷰·검증 원칙은 [AGENTS.md](AGENTS.md), 제출 전 확인 항목은 아래 [체크리스트](#응시와-제출-체크리스트)를 참고한다.

## 기능별 학습과 최종 설명

학습하는 사람은 개발자인 사용자다. 별도 Codex는 코드 설명·질문·오해 점검과 학습 노트 정리를 돕는 튜터다.

| 터미널 | Codex의 역할 | 수정 범위 |
|---|---|---|
| A: 기존 개발 창 | 기능 개발·검증·개발 기록 | 코드·CONTRACT·DECISIONS 등 과제가 허용한 개발 파일 |
| B: 새 튜터 창 | 사용자의 코드 이해·판단/AI 활용 설명 연습 지원 | STUDY.md 또는 과제가 허용한 학습 구역만 |

같은 파일시스템의 동일한 과제 루트를 사용한다. 새 터미널 B에서 아래 경로를 실제 과제 절대 경로로 바꿔 실행한다.

```sh
codex --cd "<과제 루트 절대 경로>"
```

같은 폴더의 파일을 읽으면서 각 대화 기록을 유지하는 방식이다. 폴더 지정과 대화별 파일 문맥은 [공식 Codex 안내](https://learn.chatgpt.com/docs/projects?surface=cli)를 참고한다.
B에서 [학습 세션 시작](PROMPTS.md#학습-세션-시작) 요청과 기능 인계문을 입력한다. 허용된 경우 튜터가 [STUDY 템플릿](templates/STUDY.md)을 복사해 과제 루트 STUDY.md를 만들고 내 학습 기록을 정리한다. 설명 자료 작성과 내 이해 확인 상태는 구분한다.

기능 구현·검증 또는 리뷰 수정 → A의 개발 담당자가 요구 ID·기준 버전/시점·코드/결정/검증 위치·리뷰 상태·담당 ID를 인계문으로 반환 → 사용자가 B에 전달 → 튜터가 해당 기능의 설명·질문·내 답변을 갱신한다. Kit은 터미널 자동 실행·대화 자동 전달·파일 상시 감시를 수행하지 않는다.
튜터는 실제 코드 흐름과 기록된 판단을 설명하며, 코드/개발 기록의 문제는 원래 담당자에게 돌려보낸다. 코드가 바뀌면 설명 자료는 갱신 필요, 내 이해와 최종 확인은 재확인 필요로 표시한다.

제출 전에는 [이해 확인 요청](PROMPTS.md#제출-전-이해-확인)으로 본인이 먼저 **동작·판단/검증·AI 활용과 내 판단**을 설명하고 실제 코드·기록과 대조한다. 답변이 없으면 미실행이며 AI 요약만으로 확인 완료라 하지 않는다.
내 학습 노트의 원본은 STUDY.md다. HTML 화면은 COFA 환경의 표시·실행을 확인한 뒤 선택적으로 추가한다. 학습 기록·화면에도 과제의 추가 파일·AI 사용 제한을 적용한다.

## 응시와 제출 체크리스트

과제 README와 최신 공식 안내에서 다음을 확인한다.

- **요구와 산출물:** 필수 기능·완료 기준·지정 파일명/경로·형식·제출 범위를 실제 결과와 대조한다.
- **환경과 자료:** 허용 도구·자료 반입·네트워크·외부 전송 조건과 지정 실행 명령·포트·접속 방법을 따른다.
- **검증과 저장:** 실제 실행 결과·미검증 영역을 구분하고, 저장 상태와 충돌 여부를 확인한다. 자동 검사와 사용자 직접 확인을 구분한다.
- **시간과 제출:** 과제의 제한시간·종료 시각·제출 절차를 따르고, 요구된 완료 화면/식별 정보를 확인한다.
- **본인 이해:** 핵심 로직·선택 이유·검증 근거·한계를 설명한다. AI 사용이 금지된 구간에서는 Kit의 질문·답변 보조도 사용하지 않는다.
