# 평가자 전용: 첫 분석 전에 공개하지 않음

이 파일은 실제 현업 자료가 아닌 합성 정답이다. 평가자는 질문 기록이 고정된 뒤 필요한 항목만 답한다.
한 사람이 정답을 만들고 분석하는 경우 질문 발견의 블라인드 성능은 평가할 수 없다.

| 업무 ID | 답변 규칙 | Golden Case |
|---|---|---|
| B-01 | 다른 순번의 동일 정류장은 순환 노선의 다른 경유 건이다. 유지한다 | R1: S1,S2,S1,S3, 경유 수 4 |
| B-02 | 공유 정류장은 정상 다대다. 역조회는 노선별 1건, 운휴 포함, 순서 충돌 노선 제외 | S3 → R1,R4 |
| B-03 | 완전 동일 엔터티/경유 행은 1건으로 접는다. 식별자가 같고 속성이 다르면 해당 식별자 전부 격리 | S3 2행→1, R3는 목록 제외 |
| B-04 | 같은 노선/순번에 서로 다른 정류장이 있으면 그 노선의 전체 경유를 격리. 임의 승자 금지 | R2 목록 유지, blocked=true, 경유 0 |
| B-05 | 결측 필수값/잘못된 순번/미해결 참조는 해당 행만 격리, 유효 경유의 순번을 재작성하지 않음 | R1은 1,2,3,4. S5는 유효 정류장 아님 |
| B-06 | 검색은 이름에 대해 trim+casefold 부분검색. active 필터 all/true/false. 이름 1~80자 trim, active는 JSON boolean만 허용 | active="false" → 400, false → 200 |
| B-07 | 편집은 이름/active만, 원본 불변, 재시작 후 유지. blocked 노선의 운행 여부 편집은 차단을 해소하지 않음 | R2 active 변경 후에도 blocked |

오류 노선 숨김보다 진단 가능성이 우선이다. R3 충돌 엔터티는 목록에서 제외하되 R2의 식별 정보는 확정되어 있으므로 목록과 blocked 상태를 유지한다.
빈 검색어는 전체를 의미한다. 미등록 route/stop은 404, unknown 편집 필드·빈 요청·null·숫자 active는 400.
손상된 저장 상태는 조용히 초기화하지 않고 서버 시작을 실패시킨다.
실제 순번 충돌 정답은 CSV 헤더 제외 route_stops 6,7행이다.

## 평가 운영

1. 분석자에게 README와 원본 CSV만 제공한다.
2. 질문을 먼저 기록한다. 질문의 근거와 답에 따른 구현 차이를 확인한다.
3. 위 표에서 질문에 해당하는 답만 전달한다. 질문 없이 전체 정답을 제공하지 않는다.
4. 결함별 탐지/유효 케이스별 보존 결과를 defects.json과 대조한다.
5. 기존 구현/해설/정답을 본 실험은 블라인드 지표에서 제외한다.
