## 결함·한계

자세한 재현/기대/실제/수정은 rehearsal/REVIEW.md. I01은 자연 발견 결함이 아니라 사전에 심은 결함이다.
자연 발생 과정 문제는 Windows 증거 수집 인코딩 오류였고 수정 후 재실행했다.
공개 자료 비교에서 추가로 실제 발견한 V01(무검사 통과 가능성)은 종료 상태/실행 건수 검사와 회귀6개로 수정했다.
남은 미검증: 브라우저 화면·클릭·모바일·키보드 사용성, 별도 Reviewer, 진짜 담당자 인터뷰, 180분 타이머, 새 도메인, Excel·대용량 데이터.

저장 파일 오류를 조용히 초기화하지 않는다. 사용자가 상태를 검토/백업 후 복구해야 한다.

- WHAT: 검색/필터 목록, 경유 상세, 역조회, 이름/운행 편집, 데이터 품질 보고를 구현했다.

## AI 없이 6문항: 각 5분

다음은 실제 코드 기반의 연습 질문이며 실제 출제 문항/순서를 예측하지 않는다. 답할 때 선택·근거·한계를 연결한다.

1. **`_edges()`는 왜 route+stop으로 중복제거하지 않는가?** R1의 S1 재방문, 복합키·대안·필수 규칙을 설명한다. 화면 미관/작업시간 단축은 미측정 개선 목표다.
2. **저장 버튼부터 재시작 뒤 조회까지 어디를 거치는가?** web/app.js→PATCH→app.Handler→RouteService.update→output/state.json. 원본 CSV는 유지, overrides는 재로딩됨을 설명한다.
3. **R-01~07 중 무엇을 실제로 검증했나?** AC/명령/evidence.json을 연결한다. HTTP/파생 저장은 자동 검증, 실제 Browser 조작·독립 Reviewer·180분 시험은 미검증이다.
4. **`_validate_patch()` 오류나 os.replace 실패 시 기존 결과는?** 문자열 active는400, 저장 실패는 메모리 갱신 전 실패한다. Thread RLock은 같은 프로세스만 보호하고 다중 프로세스는 미지원이다.
5. **검증기가 왜 종료0만 믿으면 안 되는가?** V01의 무검사/전부skip 사례와 새 run_suite.py의 실행/통과/skip 수·exit2를 설명한다. 21통과가 AC 완전성/새 데이터 성능/실제 플랫폼 화면까지 증명하지는 않는다.
6. **현업 규칙·AI 제안·사용자 판단을 어떻게 구분했나?** INTERVIEW의 답변은 합성 시나리오, 구현/외부 원칙 적용 판단은 AI 수행이다. 실제 사용자의 검증/거절을 꾸미지 않고 I01/V01의 관찰·수정 근거를 설명한다.
