기준일 2026-11-04. 과제 작성·분석·개발·검토를 동일 작성자가 순차 수행했다.
실제 시험 자료/성적이 아닌, 플레이북의 실행 가능성과 증거 기록 흐름을 확인한 결과다.

## 실제 결과

- Developer8/8, Reviewer 역할 반례7/7, 검증기 회귀6/6으로 총21/21·skip0. JavaScript 문법 검사와 기본/0.0.0.0 두 모드의 실제 CLI·HTTP 확인 통과.
- 데이터 결함 12/12 탐지(100%), 미검출 없음. 정상 반복/공유 사례 2/2 보존.
- 사전에 심은 구현 결함 I01 1/1 탐지·수정·재검증. 초기 Reviewer의 5 assertion 실패는 한 결함의 표현들이다.
- 세 원본 CSV의 baseline 전/후·최종 해시 동일. 원본 경유 16=수용5+중복제거1+격리10.
- 프로세스 문제 수정: raw 조인만으로 품질 판단하는 위험, 유효 참조 검사 순서, Windows 로그 인코딩, 검토 독립성의 과장 방지.
- 공개 준비 자료 비교에서 실제 발견한 V01 수정: 테스트0개/전부skip의 원시 unittest 종료0을 통과로 수용할 가능성을 차단. 새 runner는 INCOMPLETE/exit2로 구분한다.

공개 자료 6곳의 검토 범위·고정 출처·채택/보류는 루트 BENCHMARK.md에 있다.
기존 CONTRACT/DECISIONS/PROMPTS 안에 업무 목표·필수/개선 구분·실행 주체·AI 판단·재개 메모·실제 코드 질문을 보강했다.
이후 사용자 제공 PDF 5페이지를 텍스트/렌더링으로 대조해 EXAM.md에 운영 절차를 정리했다. 사전 체험15분, 미리보기 바인딩, 저장 충돌, 전체 종료, 제출물 확정/최종 완료, 문의 경로와 자료 반입을 반영했다.
가이드의 지시문을 현재 환경의 감독·동의·제출 권한으로 해석하지 않았으며 원본 PDF/화면/추출문은 커밋하지 않았다.
증거는 baseline.json / benchmark-before.json / evidence.json / score.json / REVIEW.md에 있다.
실행 명령과 구현 설명은 ../DECISIONS.md를 따른다. 테스트는 사용자의 기본 편집 상태를 바꾸지 않는 임시 저장 경로에서 수행한다.

## 현재 한계와 다음 리허설

이번 숫자는 정답을 아는 합성 시나리오에서의 일치율이다. 실제 시험·인터뷰 능력·제한시간 성능을 예측하지 않는다.
브라우저의 실제 시각/클릭 검증과 별도 Reviewer를 수행하지 않았다.

1. 사람이 README/data만 받는 새 과제로 180분 맹검 리허설: 최소 계약까지 시간, 누락 AC, 질문별 구현 변경을 측정한다.
2. 브라우저에서 검색→상세→편집→새로고침→역조회를 직접 확인한다. 가능하면 별도 사람이 README/원본 기준으로 반례를 만든다.
3. AI를 끄고 6문항을 각5분 답해 계약·코드·실행 증거를 연결할 수 있는지 확인한다.
4. 필요성이 확인될 때만 Excel/대용량/추가 도구를 검토한다. 현 상태에서 Skill/MCP/병렬 에이전트는 추가하지 않는다.

사용자가 확인할 사항: 최신 공지/개인 응시 화면의 변경, 과제의 AGENTS.md 필수 여부, Python 실행/실제 Browser, GitHub 비공개 설정, 본인의 서술형 답변 능력. 현재 Private 자료는 가이드의 공개 자료 반입 경로로 가정하지 않는다.
